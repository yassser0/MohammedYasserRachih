Data Quality & Observability Platform

Conception d'une plateforme d'ingestion et de transformation résiliente, orchestrée par Apache Airflow avec modélisation analytique sous dbt, intégrant des assertions automatiques de qualité des données et une observabilité proactive.

Rôle : Conception & Automatisation ETL Orchestration : Apache Airflow Transformation : dbt Core Conteneurisation : Docker Compose

📌 1. Aperçu du projet (Project Overview)

Dans un écosystème moderne de données, les pipelines ne doivent pas seulement déplacer la donnée : ils doivent garantir qu'elle est exacte, fraîche, complète et traçable. Ce projet implémente un pipeline de bout en bout qui extrait des données multi-sources (APIs REST et fichiers CSV hétérogènes), les charge dans un Data Warehouse (PostgreSQL / Snowflake) et applique une batterie de tests dbt à chaque exécution avant de publier les data marts aux équipes métier.

💼 2. Problématique Métier (Business Problem)

Plus de 70% des incidents en entreprise liés aux tableaux de bord décisionnels proviennent de la dégradation silencieuse de la qualité des données (« Silent Data Corruption ») :

  • Détection tardive des pannes : Les erreurs de schéma ou de valeurs nulles ne sont souvent découvertes que lorsque les utilisateurs finaux constatent des anomalies dans leurs KPI.
  • Manque d'idempotence : En cas de plantage d'un batch à mi-chemin, les relances manuelles risquent de créer des doublons ou des incohérences relationnelles.
  • Absence de lignage (Lineage) : Difficulté d'identifier l'origine exacte d'un champ calculé erroné parmi plusieurs dizaines de tables interconnectées.

🏗️ 3. Architecture Technique & Flux de Données

La solution s'articule autour d'un découplage propre entre l'orchestration, le stockage et les transformations modélisées :

Architecture du pipeline : DAG Airflow automatisé avec extraction API/CSV, validation d'intégrité, modélisation dbt et notifications Slack en cas d'anomalie.

1. Ingestion Multi-Sources & Staging

Extraction programmée depuis des APIs externes et fichiers sources avec typage fort et chargement dans la couche de staging sans altération.

2. DAG Airflow Idempotent

Gestion stricte des dépendances avec tâches isolées, politiques de retry automatiques (exponential backoff) et alertes webhook en cas d'échec critique.

3. Modélisation & Tests dbt

Transformations SQL modulaires avec tests natifs (unique, not_null, relationships, accepted_values) bloquant la propagation de données erronées.

🛠️ 4. Technologies Utilisées

Apache Airflow dbt Core Python 3.11 PostgreSQL Snowflake Docker Docker Compose Slack Webhooks Git
  • Apache Airflow : Orchestrateur de tâches avec exécuteur distribué et gestion des dépendances via des DAGs Python.
  • dbt (data build tool) : Framework de modélisation SQL déclaratif avec génération automatique de documentation et de graph de lignage (DAG).
  • PostgreSQL / Snowflake : Entrepôt de données relationnel cible gérant les schémas dimensionnels en étoile.
  • Docker & Docker Compose : Environnement entièrement reproductible isolant le scheduler, le webserver et les workers.

⚙️ 5. Étapes de Traitement & Contrôles Qualité

  1. Extraction & Ingestion : Requêtes planifiées vers les APIs sources, vérification de fraîcheur des fichiers et validation de la structure JSON/CSV.
  2. Exécution dbt test préalable : Vérification de l'unicité des clés primaires et de l'intégrité référentielle avant d'autoriser la transition vers les tables dimensionnelles.
  3. Transformation dimensionnelle : Construction de tables de faits et de dimensions (SCD Type 1 & Type 2 si applicable) pour faciliter la requête analytique.
  4. Observabilité & Alerte : Envoi automatique d'un rapport de synthèse via Slack Webhook comprenant le temps d'exécution, le nombre de lignes traitées et le statut des tests de qualité.

💻 6. Détails d'Implémentation & Robustesse

  • Idempotence garantie : Les DAGs utilisent des fenêtres temporelles déterministes (logical_date) assurant qu'une relance historique n'altère pas les données existantes.
  • Génération de documentation dbt : Documentation automatique des tables et colonnes avec visualisation interactive du lignage (lineage graph).
  • Séparation des environnements : Configuration distincte des profils dbt et des connexions Airflow entre le développement local et la production.

📊 7. Résultats, Indicateurs & Précisions
