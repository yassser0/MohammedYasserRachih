Morocco DataHub

Projet DataTech visant à centraliser, standardiser, fiabiliser et distribuer les jeux de données publics marocains (HCP, data.gov.ma, Bank Al-Maghrib) via des pipelines automatisés et une suite d’APIs REST modernes avec FastAPI.

Rôle : Architecture Data & Développement API Backend : FastAPI (Python 3.11) Base de données : PostgreSQL Documentation : Swagger / OpenAPI

📌 1. Aperçu du projet (Project Overview)

Morocco DataHub répond au défi de l’accessibilité des données nationales marocaines pour les développeurs, data scientists, économistes et entreprises. Alors que de nombreuses institutions publiques produisent des rapports statistiques précieux, ces données sont souvent dispersées dans des formats fermés ou disparates (fichiers PDF, feuilles de calcul non standardisées, portails vieillissants).

Ce projet conçoit une plateforme centralisée capable de collecter périodiquement ces sources, de les nettoyer, d'imposer un schéma relationnel strict et de les exposer au moyen d'APIs REST ultra-rapides, paginées et documentées selon la spécification OpenAPI.

💼 2. Problématique Métier (Business Problem)

  • Données morcelées et disparates : Absence de point d'entrée unique et programmable pour accéder aux statistiques démographiques, économiques ou territoriales du Maroc.
  • Formats inadaptés à l'automatisation : Fichiers souvent publiés sous formats tabulaires irréguliers nécessitant de lourds pré-traitements manuels à chaque publication.
  • Absence de documentation standardisée : Les développeurs ne disposent généralement pas d'APIs standardisées avec filtrage, pagination et gestion des types pour intégrer la donnée dans des applications web ou mobiles.

🏗️ 3. Architecture Technique

L'architecture s'appuie sur une chaîne découplée entre l'acquisition de données, la persistance relationnelle et la couche de distribution API :

Architecture Morocco DataHub : Ingestion multi-sources (HCP, open data officiel), pipelines de nettoyage, base PostgreSQL normalisée et API REST FastAPI haute performance.

1. Connecteurs & Ingestion ETL

Scripts Python dédiés à la récupération automatisée des datasets ouverts, avec détection automatique de modifications et validation de la structure entrante.

2. Stockage Relationnel Structuré (PostgreSQL)

Modélisation de schémas normalisés (régions, provinces, indicateurs économiques, séries temporelles) avec indexation optimisée pour les requêtes analytiques fréquentes.

3. Couche API REST FastAPI

Micro-service Python asynchrone exposant des endpoints sécurisés, avec validation stricte des requêtes par Pydantic et sérialisation JSON haute vitesse.

🛠️ 4. Technologies Utilisées

Python 3.11 FastAPI PostgreSQL SQLAlchemy Pydantic v2 Pandas Docker OpenAPI / Swagger Uvicorn
  • FastAPI & Uvicorn : Serveur ASGI asynchrone délivrant des temps de réponse de l'ordre de la milliseconde.
  • Pydantic v2 : Validation rigoureuse des types de données et génération dynamique des schémas JSON.
  • PostgreSQL : Moteur de base de données relationnelle robuste garantissant l'intégrité et l'évolutivité.
  • Docker : Conteneurisation de la pile applicative (API + Base de données) pour un déploiement simplifié.

⚙️ 5. Pipeline d'Ingestion & Nettoyage

  1. Extraction : Téléchargement programmé des jeux de données ouverts (données HCP, Bank Al-Maghrib et data.gov.ma).
  2. Nettoyage & Standardisation : Remplacement des valeurs manquantes, harmonisation de la graphie des noms de provinces/régions et conversion des indicateurs en unités comparables.
  3. Chargement relationnel : Insertion contrôlée dans PostgreSQL avec gestion des contraintes d'unicité et mise à jour incrémentale.
  4. Distribution & Caching : Mise en cache des requêtes courantes et exposition aux utilisateurs finaux via des routes documentées.

💻 6. Détails d'Implémentation & Fonctionnalités Clés

  • Documentation interactive : Génération automatique de Swagger UI (/docs) et ReDoc permettant aux développeurs de tester les requêtes en un clic.
  • Filtrage & Pagination : Paramètres complets pour filtrer par année, région, indicateur et pagination standardisée (limit / offset).
  • CORS & Sécurité : Gestion des headers CORS pour permettre l'intégration aisée dans des applications frontend tierces.
